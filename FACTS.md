# FACTS

Project facts that were learned the hard way. Read before deploying.

- `deploy/rolling-restart.sh` is a dry run unless given `--apply`. Deploying = rsync + pip install + `rolling-restart.sh --apply`.
  Without `--apply` the units keep running old code; check `systemctl --user show <unit> -p ActiveEnterTimestamp`.
  (2026-11-25: D-024..D-027 sat undeployed for hours because of this.)
- The engine never re-grants energy over time. WAIT gives +2 energy only by burning 1 carried material
  (cargo.ts applyCargoFuel); the zero/zero lockout rest needs energy 0 and a full hold.
- The Orin's IP is DHCP and changes (was .99, became .100 on 2026-11-25). `~/.ssh/config` uses `HostName linux.local` (mDNS). Host keys checked: ED25519 SHA256:1oUCQW2N…
- `NOEMA_PIN_PR_TOKEN` (Zero-State-LLC/Noema Actions secret) was reset on 2026-11-25 to the scrimshawlife-ctrl gh OAuth token (scopes: repo, workflow). Pin PRs open as that account. If `gh auth` on the Mac is refreshed or revoked, re-run `gh auth token | gh secret set NOEMA_PIN_PR_TOKEN -R Zero-State-LLC/Noema`.
- noema-client releases: bump `src/noema_client/_version.py` in a PR, then `gh release create vX.Y.Z --target main` (triggers the PyPI publish workflow). The Orin installs from PyPI: `~/noema-players/.venv/bin/pip install --no-cache-dir noema-client==X.Y.Z`.
- Noema and Noema-Specs require code-owner review; merges run with `gh pr merge --admin` under the standing merge grant. Noema-Specs CI checks the committed graft index: rebuild with `GRAFT_NO_GITIGNORE=1 npx -y @nanonets/graft@0.26.0 --dir graft build` and `git add -f graft`.
- Orin venv is `~/noema-players/.venv` (dot-venv). Deploy: rsync to `orin:noema-orin-src/`, `~/noema-players/.venv/bin/pip install --no-deps --force-reinstall .`, then `deploy/rolling-restart.sh --apply`. Restart only some units with `UNITS="noema-player@m03 ..."`. Never `pkill -f rolling-restart` over ssh: the pattern matches the ssh command itself and kills it.
- `rolling-restart.sh` UNITS takes full unit names: `UNITS=noema-player@m01`, not `UNITS=m01` (fails "m01.service not found").
- Office cleanup that the model won't land: `client.act(ActionProposal(action="ORG_OFFICE_RETIRE", ...))` with org_id/office_id args works; `run_macro("office retire ...")` does not. Retry on STALE_HEAD.
- Orin venv runs noema-client 0.2.0 (from noema-client main, PR #54), required by Noema-Orin #136+. Rollback copy: `~/backups/noema_client-0.1.25*` on Orin. Test venv with 0.2.0: `~/venv-020`.
- Local llama-server (T10): built at `~/llama.cpp/build/bin/llama-server` (CUDA 13.2, sm_87, about 50 min with -j3). The user unit `~/.config/systemd/user/noema-llama-server.service` is the repo unit with ExecStart pointing there, because there's no sudo for /usr/local/bin. The model `~/models/Qwen2.5-3B-Instruct-Q4_K_M.gguf` is a symlink to Ollama's qwen2.5:3b blob. Port 8081, about 2 s per constrained choice. Enable per agent by appending `NOEMA_INFERENCE_MODE=local_first`, `NOEMA_LOCAL_LLM_BASE=http://127.0.0.1:8081/v1` to `~/.config/noema-orin/mXX.env` (backup `mXX.env.bak-pre-local`).
- T12 embedder: TensorRT 11.4 is installed but there's no torch to export ONNX. Instead `noema-embed-server` (user unit, port 8082) runs llama-server `--embedding --pooling cls` on `~/models/bge-small-en-v1.5-f16.gguf` (CompendiumLabs gguf, 384-dim, about 22 ms p95). Agents use it with `NOEMA_TRT_EMBED_URL=http://127.0.0.1:8082/v1` (OpenAI shape, auto-detected by the `/v1` suffix).
- Never run `pkill -f "port 8082"` over ssh: the pattern matches the ssh command itself (same trap as rolling-restart).
- Dashboard (D-077): `noema-dashboard` (user unit, 127.0.0.1:8787, about 15 MB). The Orin is headless (tty session, no X/Wayland, no Chromium), so `noema-dashboard-kiosk` is NOT installed. View it from the Mac with `ssh -N -L 8787:127.0.0.1:8787 orin`, then open http://127.0.0.1:8787. Pre-D-077 player unit backup: `~/backups/noema-player@.service.pre-d077`.
- Monitor kiosk (D-077): the Orin boots to multi-user.target (gdm off). A 4K monitor is on DP-1. The system unit `/etc/systemd/system/noema-dashboard-kiosk.service` (enabled) runs `xinit deploy/jetson/kiosk-xinitrc` on vt1, which starts `kiosk.py` (GTK + WebKit2 4.1, no Chromium). It sizes itself to the screen (no WM, so fullscreen() alone gives a 200x200 window), zooms 2x on 4K, blanks DPMS, and reloads every 30 min. Screenshot the panel with `DISPLAY=:0 python3` and Gdk.pixbuf_get_from_window. WebKit uses about 650-740 MB RSS.
- RAM steady state with everything up (6 agents, llama 3B, embed, dashboard, kiosk): about 1.5 GB available. More agents on local_first/embedder share the existing servers, so the extra RAM is small.
- Transition logs (`~/noema-players/mXX/mind/transitions.jsonl` plus rotated `transitions-00000N.jsonl.gz`): a turn row's `ts` is epoch seconds (a float), not ISO. Outcome rows have no `ts`; join them to turn rows on (session, turn). Outcome rows are written only when a session ends (`record_outcomes`), so a freshly restarted agent shows 0 labelled turns until its first session closes, and a session that ends in a transport drop is never labelled. Always read the `.gz` segments too. (2026-11-28: a string cutoff silently matched nothing, and a live-segment-only replay saw 6 of 49 turns.)
- To start a long job on the Orin without holding the ssh session open, redirect stdin as well: `nohup cmd > /tmp/x.log 2>&1 < /dev/null &`. Check on it with a separate `ssh -o BatchMode=yes orin '...' < /dev/null`.
