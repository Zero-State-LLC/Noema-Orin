# Keep synthetic run outcomes distinct and safe

The Orin foundation validates its explicit target profile before reading a fixture or invoking an adapter, then validates fixture and proposal before client submission. Every invocation emits exactly one allowlisted JSON outcome on stdout: a pre-submission refusal, a failed submission attempt, or an `ATTEMPTED` fake-client handoff. Errors exit nonzero without raw exceptions or private inputs on either output stream; neither failures nor handoffs retry or cross profile boundaries. We chose this explicit boundary over bubbling exceptions or treating all errors as one generic attempt because those alternatives conceal whether an action reached the client, and a fake success must never be read as world acceptance. This decision applies only to the local synthetic foundation; it grants no live-world or offline-Spark authority.
